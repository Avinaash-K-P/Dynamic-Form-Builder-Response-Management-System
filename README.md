
# Dynamic Form Builder & Response Management System

## 1. Title

**Dynamic Form Builder & Response Management System**

A full-stack application that enables users to create and manage dynamic forms without modifying application code. The system supports multiple field types, input validation, conditional logic, response management, analytics, and export functionality.

The platform includes role-based access control, JWT authentication, Redis caching, asynchronous notification processing, and activity logging.

## 3. MySQL Database Schema

The application uses **MySQL 8.0** as its relational database, with SQLAlchemy for ORM operations and Alembic for database migrations.

### Database Tables

| Table                | Purpose                                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------------- |
| `users`            | Stores user accounts and authentication-related information.                                             |
| `roles`            | Defines application roles, including admin and regular users.                                            |
| `forms`            | Stores form titles, descriptions, ownership, active status, and timestamps.                              |
| `form_fields`      | Stores dynamic form fields, field types, validation rules, conditional logic, and display configuration. |
| `field_options`    | Stores selectable options for supported fields, such as dropdowns, checkboxes, and radio buttons.        |
| `form_responses`   | Stores submitted form responses and associated metadata.                                                 |
| `response_details` | Stores individual field responses using JSON-compatible values.                                          |
| `activity_logs`    | Records important application activities for auditing and review.                                        |
| `notifications`    | Stores user notifications, including notifications generated by background tasks.                        |
| `exports`          | Tracks Excel and PDF export requests, their status, and generated file information.                      |

### Database Features

* Relational data management using MySQL.
* SQLAlchemy ORM for database operations.
* Alembic migrations for schema versioning.
* Foreign-key relationships between related entities.
* JSON storage for flexible response values, validation rules, and conditional logic.
* Role-based authorization for protected operations.
* Pagination and filtering for supported list endpoints.
* Redis caching for selected frequently accessed data.

### Database Migrations

Apply the database migrations using Alembic:

```bash
alembic upgrade head
```

To create a new migration after modifying the SQLAlchemy models:

```bash
alembic revision --autogenerate -m "describe your changes"
```

Review the generated migration before applying it to the database.

## 4. Docker Configuration

Docker Compose is used to manage the backend application and its supporting services.

### Services

| Service           | Purpose                                                                        |
| ----------------- | ------------------------------------------------------------------------------ |
| `backend`       | Runs the FastAPI application and exposes the REST API on port`8000`.         |
| `mysql`         | Runs the MySQL 8.0 database service.                                           |
| `redis`         | Provides Redis caching and the Celery message broker.                          |
| `celery_worker` | Processes asynchronous background tasks, including notification-related tasks. |

### Configuration Files

```text
backend/
├── Dockerfile
├── docker-compose.yml
├── .dockerignore
├── .env
├── requirements.txt
├── alembic.ini
├── alembic/
└── app/
```

### Environment Variables

Configure the required variables in the backend `.env` file.

```dotenv
MYSQL_ROOT_PASSWORD=your_root_password
MYSQL_DATABASE=dynamic_form_db
MYSQL_USER=dynamic_form_user
MYSQL_PASSWORD=your_database_password

DATABASE_URL=mysql+pymysql://dynamic_form_user:your_database_password@localhost:3306/dynamic_form_db

SECRET_KEY=your_secret_key
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRY_MINUTES=30
REFRESH_TOKEN_EXPIRY_DAYS=7
RESET_TOKEN_EXPIRY_MINUTES=15
```

**Important:** Replace the example credentials and secret key with your own values. Keep `.env` out of version control. The `DATABASE_URL` above is for running the backend directly on your host; Docker Compose should override the database hostname with the MySQL service name, `mysql`.

If your database password contains special characters, URL-encode it when constructing the database connection URL.

### Build and Run

Run the following commands from the backend directory.

**1. Validate the Docker Compose configuration**

```bash
docker compose config
```

**2. Build the application image**

```bash
docker compose build
```

**3. Start the services**

```bash
docker compose up -d
```

**4. Check running containers**

```bash
docker compose ps
```

**5. Apply database migrations**

```bash
docker compose exec backend alembic upgrade head
```

**6. View backend logs**

```bash
docker compose logs -f backend
```

**7. View Celery worker logs**

```bash
docker compose logs -f celery_worker
```

**8. Stop the services**

```bash
docker compose down
```

To stop the services and remove their containers while preserving named volumes:

```bash
docker compose down
```

The MySQL and Redis data volumes preserve their data when containers are stopped and removed. Do not use `docker compose down -v` unless you intend to delete the associated persistent volumes.

### Access the Application

Once the backend is running, the API is available at:

* **Backend API:** `http://localhost:8000`
* **Swagger UI:** `http://localhost:8000/docs`
* **ReDoc:** `http://localhost:8000/redoc`

The React frontend can run separately during development, provided its API base URL points to the backend.

### Authentication and Authorization

* JWT access tokens protect authenticated endpoints.
* Refresh tokens support access-token renewal.
* Role-based access control distinguishes administrators from regular users.
* Protected endpoints can be tested in Swagger by using the **Authorize** button and supplying a valid bearer access token.

Use the format required by Swagger's authorization dialog, typically:

```text
Bearer <access_token>
```

### API Testing Workflow

1. Open Swagger UI.
2. Register a user or log in with an existing account.
3. Copy the access token from the login response.
4. Authorize Swagger using the token.
5. Test the endpoints according to their required roles and request schemas.
6. Verify the responses and database changes.
